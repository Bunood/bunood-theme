{#- ============================================================================ Bunood Letter Head — FOOTER ---------------------------------------------------------------------------- Owner's spec: address, phone, email — all read from the company's own data. THE ADDRESS BUG THIS FIXES The previous version read a custom field `custom_company_address`. No such field exists on Company, on this stack or in stock ERPNext — measured: the Company doctype carries phone_no, email and website, and an `address_html` DISPLAY field, but no plain address. So the footer's address line silently never rendered, which looks exactly like "the company has not filled it in". ERPNext keeps the address in the Address doctype, joined through Dynamic Link. That is what this reads: the primary billing address if one is flagged, otherwise the first address linked to the company. SELF-CONTAINED inline styles (a PDF footer renders in isolation — theme CSS never reaches it). Colours are --bnd-* tokens (written as CSS custom-property references), substituted per site at sync exactly as the header's are — see the header's comment for the mechanism. Phone, email and website are isolated in dir="ltr" spans so bidi never reorders +966… or a URL. Every line is guarded and so is the whole block: a company with no contact data prints no rule and no band at all, rather than an empty grey strip. ============================================================================ -#} {%- set _c = frappe.get_doc("Company", doc.company) if doc and doc.get("company") else None -%} {%- set phone = (_c.get("phone_no") if _c else "") -%} {%- set email = (_c.get("email") if _c else "") -%} {%- set website = (_c.get("website") if _c else "") -%} {%- set privacy = (_c.get("custom_privacy_policy") if _c else "") or (_c.get("custom_privacy_policy_url") if _c else "") -%} {#- Address lives in its own doctype, joined by Dynamic Link.
